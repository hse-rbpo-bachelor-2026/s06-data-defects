# S06. Учебное API «Заметки»

Учебный объект `s06-data-defects` для семинара «Исправление дефектов обработки данных». Приложение содержит намеренные дефекты. Работайте локально на `localhost`; используйте только учебные данные. Это лабораторный объект, а не образец реализации продукта.

Вы получили чужое приложение и три жалобы: поиск иногда показывает чужие заметки; при ошибке создания заметки клиент получает технические подробности; получение вложений, возможно, позволяет читать другие файлы. На занятии первый случай разбирается с преподавателем, второй — совместно, третий — самостоятельно.

## 1. Подготовка и запуск

Нужны Git и стабильный .NET SDK 10. Файл `global.json` разрешает стабильные обновления SDK внутри ветки 10.0; SDK 9 или один runtime не подходят. Для демонстрации используется Windows, VS Code, расширения C# Dev Kit и REST Client (`humao.rest-client`). Расширения рекомендованы в `.vscode/extensions.json`. Docker для S06 не нужен. Прямые и транзитивные пакеты зафиксированы файлами `packages.lock.json`; команда `restore --locked-mode` проверяет согласованность состава.

Получите архив или репозиторий по ссылке преподавателя. Откройте в VS Code именно папку `s06-data-defects`, где находятся `NotesApi.slnx` и `requests.http`. Все команды выполняются из этой папки.

В PowerShell:

```powershell
dotnet --version
dotnet restore --locked-mode
dotnet test
```

На старте ожидаются 5 пройденных тестов и 3 пропущенных учебных заготовки. Это подтверждает штатные функции, а не отсутствие дефектов.

В первом терминале:

```powershell
dotnet run --project src/NotesApi --urls http://localhost:8080
```

Терминал остается занят приложением. Откройте `requests.http`, нажмите **Send Request** над запросом 0. Ожидаемый ответ: `200`, `{"status":"ok"}`. Тесты запускайте во втором терминале. Они используют собственный сервер внутри процесса и собственные временные данные; отдельный запущенный API им не нужен.

После изменения исходного кода остановите API через Ctrl+C и запустите снова. Автоматическое обновление кода не предполагается.

## 2. Данные и границы модели

На свежих данных у `alice` две заметки с текстом `private`, у `bob` одна заметка с текстом `bob secret note`. Пользователь задается заголовком `X-User`. Это учебная подстановка уже определенной личности; аутентификация на S06 не моделируется. Подмена самого заголовка не является задачей этой лабораторной.

При поиске учитываются владелец и поисковая строка. При создании заметки пустой текст должен отклоняться. Приложение выдает текстовые вложения. Каталог вложений и служебный демонстрационный файл создает сам стенд; служебный файл не должен выдаваться через API вложений.

Данные обычного запуска сохраняются в `lab-data` рядом со сборкой: обычно `src/NotesApi/bin/Debug/net10.0/lab-data`. Тесты создают отдельные каталоги во временной директории и удаляют их после выполнения. Переменные `NOTES_DB_CONNECTION` и `NOTES_ATTACHMENT_ROOT` — дополнительные настройки; для занятия оставьте их незаданными.

## 3. Работа на занятии

### Первый блок — поиск

Выполните запросы 1–3 в `requests.http`, сравните владельцев. Зафиксируйте запрос, пользователя и фактический ответ. Затем откройте `NotesRepository.Search` и объясните механизм нарушения.

В `tests/NotesApi.Tests/NotesTests.cs` снимите `Skip` только с первого негативного теста и запустите:

```powershell
dotnet test --filter FullyQualifiedName~Search_Injection
```

До исправления этот тест должен падать на наблюдаемом нарушении, после — проходить. Исправьте установленную причину вместе с преподавателем и повторите обычный поиск, специальный запрос и весь набор активных тестов. Запрос 4 предназначен для эксперимента с апострофом.

### Второй блок — ошибка создания

Выполните запросы 5–8. Сравните корректную заметку, пустой текст и поврежденный JSON. Отделите ошибку клиента от внутреннего сбоя. Найдите в `Program.cs` место передачи внутренних подробностей в ответ.

Совместно сформулируйте ожидаемый ответ и закончите заготовку `Create_Invalid_Json_Is_Rejected_Without_Internal_Details`. Удалите `NotImplementedException` после добавления проверок, снимите `Skip`, наблюдайте падение до изменения. После исправления повторите тест и штатное создание заметки. Сохраните фактические результаты; проверьте также лог, не приписывая ему утечку, которой не наблюдали.

### Третий блок — самостоятельная проверка вложений

Жалоба: «Через получение вложения можно достать не только вложения». Сначала выполните запрос 9. Затем самостоятельно постройте запрос, который проверяет жалобу, найдите причину, исправьте ее и закончите заготовку `Attachment_Outside_Root_Is_Not_Returned`.

Не ограничивайтесь отказом на один конкретный текст запроса: объясните, какое условие должно выполняться для итогового пути. Негативный тест должен воспроизводить нарушение на исходной реализации. После изменения проверьте и недопустимое чтение, и получение `welcome.txt` с правильным содержимым.

Для быстрых: после завершения третьего блока исследуйте `/notes/by-tag`. Дополнительный материал `reserve/` используется только по указанию преподавателя.

## 4. Что предъявить

К концу занятия предъявите учебную цепочку по третьему дефекту: сценарий и результат до изменения; причина; исправление; негативная и регрессионная проверки; фактический результат на исправленной версии. Используйте форму из карточки S06 курса. Ссылок на существующие код, тесты и вывод достаточно; отдельный большой отчет не нужен.

Для сохранения вывода:

```powershell
dotnet test --logger "trx;LogFileName=s06-tests.trx" --results-directory TestResults
git status --short
git rev-parse HEAD
```

Если изменения еще не закоммичены, укажите исходный commit и приложите `git diff`, называя состояние рабочей копией. Hash исходного commit не обозначает исправленную версию без сведений об изменениях. В архивной копии Git-истории нет: можно выполнить `git init`, создать исходный commit, а исправления фиксировать дальше. Git-настройку имени и почты используйте свою; публикация копии в GitHub для S06 не обязательна.

Один полный прогон после исправления может одновременно подтверждать негативную проверку, регрессию и повторную проверку. Повторять неизменный прогон ради дополнительного пункта не требуется.

## 5. Сброс перед новой демонстрацией

Остановите API через Ctrl+C, затем:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\reset-demo.ps1
```

Команда разрешает выполнение только для запуска этого локального скрипта и не меняет политику Windows постоянно. Скрипт удаляет только автоматически созданные каталоги `lab-data` внутри `src/NotesApi/bin`; исходный код и результаты тестов сохраняются. Следующий запуск восстановит исходные данные. Если заданы внешние пути через переменные окружения, они этим скриптом не сбрасываются.

Сброс данных не возвращает уязвимый исходный код. Для следующей группы используйте свежую копию стартового архива либо известный стартовый commit; свои исправления предварительно сохраните.

## 6. Если запуск не удался

- `dotnet` не найден: установите SDK 10, откройте новый терминал и проверьте `dotnet --list-sdks`.
- Восстановление пакетов не прошло: прочитайте первую ошибку NuGet; проверьте доступ к источнику пакетов. После успешного восстановления локальные запуски не требуют внешнего API.
- Порт занят: используйте `--urls http://localhost:8081` и замените `@baseUrl` в `requests.http`.
- Нет **Send Request**: установите REST Client и убедитесь, что открыт файл `.http`.
- Код изменен, ответ старый: остановите и заново запустите API.
- Под тестом остался `Skip`: он не выполнялся, зеленый итог не подтверждает эту проверку.
- После снятия `Skip` падает `NotImplementedException`: заготовка еще не закончена; это не доказательство дефекта.

Если не успели, предъявите воспроизведенное нарушение и причину, затем завершите учебную цепочку до S07 по порядку преподавателя. Перенос на собственный проект описан в карточке S06. Искусственно добавлять уязвимость в командный продукт не требуется.
